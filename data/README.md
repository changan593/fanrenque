# data —— 机器产出的数据资产

**这里的东西全部由 `pipeline/` 的脚本算出来，删了能重跑。**
所以要改这里的内容，正确做法通常是去改产生它的脚本，而不是手改文件。
（对照：`production/` 里的东西是人写的，删了就没了。）

每个文件、每个字段的详细含义见 [`../doc/09_数据字典.md`](../doc/09_数据字典.md)。

| 目录 | 内容 | 产出脚本 |
| --- | --- | --- |
| `chapters/` | 逐章分析，一章一个 `chNNNN.json`，共 1200 个 | `s2` / `s2m` / `s5` |
| `characters/` | 角色资产 973 个 + 角色卷宗 + 14 份深度档案 | `s4` / `s8` |
| `scenes/` | 场景资产 1364 个 | `s4` |
| `plot/` | 全书结构：剧情线、六季、分集表、长线、体检报告 | `s0` / `s3` / `s9` / `s10` / `s11` / `s12` |

## 三种容易搞混的角色文件

`characters/` 里有三类文件名，各干各的，不要混用：

| 文件 | 是什么 | 谁写的 |
| --- | --- | --- |
| `cNNN_名字.json` | **角色资产**：出场章节、称呼、原文描写汇总、关系 | `s4` 从 1200 份分析聚合 |
| `dossier_名字.json` / `.md` | **原文卷宗**：这个角色在全书的每一次出现 + 上下文 | `s8` 从原文扫描 |
| `名字_角色深度档案.md` | **深度档案**：性格、轨迹、关系的成文分析 | 人（读卷宗后逐字取证写成） |

写角色文档的顺序是 **卷宗 → 深度档案**，不能跳过卷宗直接写——
凭印象写人物等于把没验证过的东西往下游传，违反原则二。
