## 三、⚠ 一个要修正的旧说法

`doc/01_原文数据说明.md` 早先写的是「约 22 章的内容丢失」，隐含的意思是
「每组里有一章是完整的，另外那 22 章整章没了」。**这个说法不准确，缺的比那更碎。**

实际是**每一章都被截了一段**，不是整章整章地掉。三条证据：

1. **`seq1167` 里有站点的截断填充**。正文第 16 段停在
   「唐真记起来了，刚才那人」——句子没写完；紧接着第 18~35 段全是单个「。」，
   共 18 行。这是站点用来占位的省略，不是原文。
2. **`seq1118` 里两章的内容都在，但都只有一半。** 第 0~27 段是第 1115 章
   「茶庄乞丐，独夫女孩」的内容，第 29~61 段是第 1116 章「命河长短，螺生早晚」
   的内容，中间用「。。。」分场。两段各约 1000 字，都不足一章。
3. **`seq1118` 的第一句是半截的**。它以「主事深吸一口气，走了过去」开头——
   「主事」这个人没有被介绍过。而前一单元 `seq1117`（第 1114 章）
   结束在姜赢与程百尺的书院线，跟茶庄毫无关系。中间断了。

**所以这 41 章要整章重补，不能只补那 22 章。** 只补 22 章的话，
另外 19 章仍然是残的，第六季照样写不出来。

## 四、补进来之后怎么处理

原文格式与现有 `source/*.txt` 保持一致即可（章节标题独占一行，
形如 `第1115章茶庄乞丐，独夫女孩`），编码 GB18030 或 UTF-8 都行。

```bash
# 1. 把补齐的文本放进 source/，然后重跑标准化
python pipeline/s1_normalize_novel.py

# 2. 确认 is_merged 的单元已归零
python -c "
import json; ch=json.load(open('source/novel.json'))['chapters']
m=[c['seq'] for c in ch if c.get('is_merged')]
print('仍受损的单元：', m or '无')"

# 3. 只跑新增/变动的章节的分析（花钱，但只花这几十章的）
python pipeline/s2_analyze_chapters.py --range 1115 1210
python pipeline/s3_validate_chapters.py

# 4. 重建下游资产与分集表（都不花钱）
python pipeline/s4_build_assets.py
python pipeline/s9_plot_digest.py
python pipeline/s12_detect_arcs.py
python pipeline/s10_episode_plan.py
python pipeline/s11_episode_assets.py
```

**注意 `seq` 会变。** 现在 19 个合并单元各占一个 `seq`，补齐后会拆成 41 个，
全书分析单元数从 1200 涨到约 1222，第 1118 号之后的所有 `seq` 全部后移。
所以补完之后 `data/plot/` 里的分集表、卷段、时间线都要重跑——
上面第 4 步就是干这个的。**第 1~1117 号单元不受影响，前五季的一切结论都不用动。**
