# 画风选型矩阵测试

> **✅ 选型已结束。** 结论：国风三维（`doc/04` 3.1）。
> 本文保留为**操作手册与留痕**——以后要复盘"为什么选这个画风"，或要再跑一次对比时，
> 配置和跑法都还在。`production/style_test/matrix.json` 不再是生产依据；
> 生产用的风格段在 `production/style_assets/`。

**目的**：用一次受控实验，把「整部剧用什么画风」这个决定从感觉变成证据。

**产出**：一张大对比图。横轴是十一种画风，纵轴是十个画面目标，每格三张 16:9 图。
你扫一遍就能知道哪个画风在我们真正要拍的画面里扛得住、哪个一看就废。

## 一、为什么是这十个画面目标

不是随便挑十个好看的画面。是从**已经写完的 E01／E02 两集共 409 个镜头**里统计出来的
真实构成，加上这部书特有的、最容易翻车的几种画面。

统计结果：中景及更近占 **76%**，广角只占 **10%**，全剧预估 **63,000 个镜头**。
所以测试必须压在人脸和中近景上，而不是拿几张好看的大场面来选画风——
那等于用 10% 的画面去决定 90% 的成败。

| ID | 画面目标 | 为什么必须测它 |
| --- | --- | --- |
| T01 | 单人近景独白 | 全剧最高频镜别。测人脸结构、额头黑印这个跨集锚点、单一光源、脏旧质感 |
| T02 | 双人中景对手戏 | 本剧主体形态，每集 144 条台词绝大多数是两人对话。测两张脸同时可控、16:9 横向空间关系 |
| **T03** | **老年角色特写·反美化** | **★ 最关键。** 原著的美学是「长得并不出彩」，而所有生图模型都强烈偏向美化。这一格直接决定淘汰名单 |
| T04 | 少女情绪特写·反过度美型 | 测「有辨识度的清秀」而不是「标准美人模板」，以及桃木枝这种粗糙道具会不会被改成精致发簪 |
| T05 | 多人群像 | 施粥场四五十个乞丐。测人群会不会糊成一堆融合的脸和肢体 |
| **T06** | **环境空景·无阴影规则** | **★** 洞天桃花崖设定为无影之地。测这个画风能不能被约束住去违反模型的物理直觉——有影子即不合格 |
| T07 | 夜戏单光源 | 破庙火光自下而上。测暗部有没有细节，还是死黑一片 |
| T08 | 手与物件特写 | 生图模型的传统重灾区。测手指数量、关节、掌纹老茧，以及银锭的「成色差」而非「亮元宝」 |
| T09 | 术法瞬间·要求不炫 | 测能不能压住模型加魔法阵和彩色粒子的本能。原著里喷火放电被角色称作「街边杂耍」 |
| T10 | 大远景奇观·要求克制 | 剑芒横跨一洲。测能不能只画一道细而锐利的线，而不是自作主张加爆炸和光晕 |

T03 和 T06 是**淘汰赛**，不是评分项。它们不合格的画风直接出局，
后面几项再好看也没用——因为那不是这部书。

## 三、单一变量原则（这是这次测试成立的前提）

每格的提示词都是拼出来的，不是逐格手写的：

```
公共前缀（题材＋画幅）
  ＋ 目标描述（只写画面里有什么，绝不写怎么渲染）
  ＋ 画风段（只写怎么渲染，绝不改画面内容）
  ＋ 公共后缀（全局质感规则）
  ＋ 「务必避免出现以下要素：…」
```

**十个目标描述在八个画风下逐字相同，只有画风段在变。**
如果逐格微调提示词，出来的差异就无法归因——分不清是画风的差异还是描述的差异，
整个矩阵就白做了。所以：

> 要调，改 `production/style_test/matrix.json` 里的目标描述或画风段。
> **不要手改 `prompts.md`**，它是每次现拼的，改了不生效。

另外，OpenAI Images API **没有 `negative_prompt` 字段**。
所以反面词由脚本去重合并后，以自然语言追加在提示词末尾。这是接口限制下唯一的做法。

## 三点五、尺寸这一格最容易踩

按 OpenAI 官方 Images API 对接，`base_url` 与密钥走 `.env`，指向哪个网关都行。
但**各模型的尺寸档位是不通用的**：

| 模型 | 官方支持的尺寸 |
| --- | --- |
| `gpt-image-*` | `1024x1024` · `1536x1024` · `1024x1536` · `auto` |
| `dall-e-3` | `1024x1024` · **`1792x1024`** · `1024x1792` |
| `dall-e-2` | `256x256` · `512x512` · `1024x1024` |

拿 `1792x1024` 配 `gpt-image` 会被上游拒掉，而网关多半把它包成
**502「Upstream network error」**——看着和网络故障一模一样。
脚本现在**在发请求之前就自查**，直接说清是哪个模型配了谁家的档位，
不再花一次请求去换一个看不懂的 502。

**16:9 怎么来的**：接口一个 16:9 档位都没有。与其迁就，不如出完自己裁——
默认取 `1536x1024`（gpt-image 的官方横版档，3:2），出图后居中裁成精确
`1536x864`。全片画幅已定 16:9，测试图就该按成片画幅看。
不想裁就设 `IMAGE_CROP_169=0`。

**可选参数**（`quality` / `moderation` / `output_format` / `background`）
只在 `.env` 里填了才发，网关不认某个参数会直接 400，脚本会自动摘掉重试，
不让整格因此报废。其中 `IMAGE_MODERATION=low` 是有意为之：
我们的提示词里全是「缺牙」「丑陋」「肮脏」「乞丐」，默认审核档容易误伤。

## 四、怎么跑

### 0. 准备

```bash
pip install -r requirements.txt          # 需要 Pillow
cp .env.example .env                     # 填 IMAGE_API_KEY
```

字体：拼图需要中文字体，缺了会全是豆腐块。
`sudo apt-get install -y fonts-wqy-zenhei`（或用 `--font` 指定路径）。

### 1. 先看提示词，不花钱

```bash
python pipeline/s6_style_matrix.py --dump      # 导出全部 80 条到 production/style_test/prompts.md
python pipeline/s6_style_matrix.py --dry-run   # 只报要发多少请求
```

### 1.5 出错了先跑体检

```bash
python pipeline/s6_style_matrix.py --doctor
```

阶梯式加压，一次只动一个变量，**第一个失败的台阶就是病因**：

```
[1/4] 接口连通 + 密钥 + 模型名      极短提示词 + n=1 + 1024x1024
[2/4] 目标尺寸                     只换尺寸
[3/4] 真实长度提示词（约 650 字）   只换提示词
[4/4] 单次出 3 张（n=3）           只换张数
```

每一级各给一句可直接执行的处置。只有第一级失败时才可能是「上游整体不可用」——
第二级往后失败说明前面的请求成功过，上游显然是活的。

### 2. 先小范围试水（**强烈建议**）

别一上来就 240 张。先拿最关键的一格试：

```bash
python pipeline/s6_style_matrix.py --targets T03 --styles S6
```

确认出来的图是那个意思，再全量。

### 3. 全量

```bash
python pipeline/s6_style_matrix.py
```

10 目标 × 11 画风 × 3 张 = **330 张**，单次请求 `n=3`，约 **110 次请求**。

只想先看新加的那三个画风：

```bash
python pipeline/s6_style_matrix.py --targets T03,T06 --styles S9,S10,S11   # 18 张，约 6 次请求
python pipeline/s6_style_matrix.py --styles S9,S10,S11                     # 90 张，约 30 次请求
```

断点续传是按张算的：已存在的图不会重出，一格只出来 2 张下次就只补 1 张。
中断了直接重跑同一条命令即可。

### 4. 拼大图

```bash
python pipeline/s7_contact_sheet.py
```

产出在 `production/style_test/sheets/`：

| 文件 | 内容 | 什么时候看 |
| --- | --- | --- |
| `master.jpg` | 总表，10 目标 × 11 画风 | 最后看整体 |
| `by_target/T03_*.jpg` | 单个画面目标，八种画风横向排开，图更大 | **先看这个，判生死** |
| `by_style/S6_*.jpg` | 单个画风，十种画面横向排开 | 查这个画风有没有短板 |

图还没出全也可以拼，缺的会画成「缺图」占位。

## 五、看图的顺序（重要）

**不要一上来就看哪个好看。** 按这个顺序淘汰：

1. **`by_target/T03` 老年角色特写。**
   出来的人必须让你觉得不太想靠近。缺牙必须真的缺，皱纹必须像干裂的泥地，脸必须脏。
   **看着像可爱老爷爷的，直接淘汰。**
   这一关卡的是模型的美化本能——顶不住，后面 63,000 个镜头全都会往偶像剧上漂。

2. **`by_target/T06` 洞天无阴影。**
   地面上有没有投影？树、楼、石桌、山道全都不能有。**有影子即淘汰。**
   这一关卡的是可控性——连一条明确的规则都约束不住的画风，
   后面几百集的一致性锁定项根本无从谈起。

3. **`by_target/T08` 手与物件、`T05` 多人群像。**
   这两项看的是崩坏率。手指数量、人群融合——它们决定返工率，直接换算成工期。

4. **`by_style/*` 逐个画风体检。**
   剩下的画风，看它在十种画面里有没有明显撑不住的一类。
   某一类翻车就意味着那一类镜头得单独另想办法，成本会失控。

5. **最后才看 `master.jpg`，看哪个顺眼。**

前四步是排除法，只有活到第五步的才轮到审美。这个顺序不能反——
反过来就会选中一个好看但撑不住 63,000 个镜头的画风。

## 六、选完之后要同步的地方

定下画风后，风格段要写回这些文件，否则会各处不一致：

- `doc/04_风格规范.md` 第三节、第十四节 A 项
- `production/s01/02_角色资产.md` 各角色的 base prompt
- `production/s01/03_场景资产.md` 各场景的 base prompt
- `production/s01/E01_剧本.md`、`E02_剧本.md`
- `doc/05_唐假旁白系统.md` 的 Q 版提示词

## 七、已知限制

- **尺寸**。接口一个 16:9 档位都没有，所以默认 `1536x1024` 出图后裁成 `1536x864`。
  见第三点五节。
- **一致性不在本轮测试范围**。这轮测的是「画风对不对」，
  不是「同一个角色出两次像不像」。角色一致性要等画风定了之后，
  用参考图 + `/images/edits` 单独验证（待办事项 2）。
- **每格三张的差异**只反映模型自身的随机性。三张差异过大本身就是一个负面信号：
  说明这个画风在这类画面上不稳定，量产时返工率会很高。
