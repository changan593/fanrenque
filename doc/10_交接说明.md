## 一、这个项目在做什么

把中文网络小说**《穿越后，系统变成白噪音了怎么办》**（作者：码字的画家，1200 章，
290 万字）改编成 **AI 漫剧**——用 AI 生图/生视频做成约 **268 集**、每集约 28 分钟的动画剧。

### 三条不可违背的原则（用户定的，任何时候不许绕过）

1. **最终目标是高质量成片。** 所有环节都要谨慎细致，人物场景必须高一致性。
2. **严格遵守原文。** 原文有多少场景人物就多少，原文怎么描写就怎么呈现。
   **人物对话、心理活动、关键旁白一条都不能漏。** 不许为了戏剧效果自行发挥。
3. **画面朴素真实，严禁浮夸。**

> 原则二是这个项目所有技术设计的源头。「逐字核验」「位置引用」「台词覆盖率」
> 这些机制存在的唯一理由就是它。**任何时候不要为了省事绕过逐字校验。**

### 原则三不是外部约束，是作者本人的审美

这一条容易被误解成「我们给它加的限制」，不是。全文词频：
「闪耀」1 次 vs「脏」152 次；书里有角色管喷火放电叫「街边杂耍」。
按原著写就是朴素的，浮夸才是背叛原文。

## 五、必须知道的坑（都是踩过的）

### 5.1 DeepSeek 的思考模式默认是开的

官方文档：「思考模式默认打开，且 effort 默认为 high」。而逐章分析是**抽取**任务
不是推理题，开着它有三个坏处：思维链和正式回复抢 `max_tokens`（长章节直接把
`content` 挤成空）、官方已载明 JSON 模式本身就有概率返回空 content（两者叠加时
空回复率极高）、思考模式下 `temperature` **不生效**。

**代价是实打实的**：一次 500 章的跑批耗了 6 小时 45 分，只成功 9 章。

现在 `.env` 里 `LLM_THINKING=0` 是默认值，**保持不动**。客户端永远显式声明
`thinking` 字段而不依赖服务端默认值——默认值会变，代码里的不会。

### 5.2 重试必须是自适应的

对确定性错误原样重试毫无意义。现在每次重试都会**改一个参数**：
空回复 → 先摘 JSON 模式再关思考模式；`finish_reason=length` → `max_tokens` × 1.5；
JSON 解析失败 → 摘掉 JSON 模式。详见 `pipeline/README.md`。

### 5.3 出图接口的尺寸档位不通用

`gpt-image-*` 只认 `1024x1024 / 1536x1024 / 1024x1536 / auto`；
**`1792x1024` 是 dall-e-3 的档位**。拿错了会被上游拒掉，网关多半包成
**502「Upstream network error」**，看着像网络故障。
`s6` 现在会在发请求前自查并说清楚。

### 5.4 别名归并会把全书角色塌成一个人

`s4` 用并查集归并别名。**一条错别名就能毁掉整个资产库**——seq369 把「求法真君」
（唐真的名号）写成了尉天齐的别名，不拦住会把 973 个角色塌成一个「唐真」，出场 1199 章。

现在的防线有两道：泛称（老人/女人/小丫头/…）不参与归并；
**闸门建在簇上而非成对判断**（并查集有传递性，成对检查挡不住）。
人工核实过的身份从 `s8` 的 `PRESETS` 读入，优先于自动闸门。

### 5.5 `.env` 的行尾注释

`.env.example` 里写满了 `LLM_TIMEOUT=600  # 单次请求总时限` 这样的说明。
解析器现在会剥掉行尾注释——但**只认「空白 + #」**，因为密钥里可能带 `#`。

### 5.6 别名表拉平成字典会把主角算成配角

5.4 说的是**归并那一步**的防线。这一条说的是**事后又把别名表当查找表用**的坑，
`s11` 踩了。

`index.json` 的别名表里有 **305 个歧义名**：212 个被两个以上主名同时认领，
155 个本身又是别的主名。`s11` 把它拉平成 `别名 → 主名`、后写覆盖，
于是谁覆盖谁只取决于索引顺序。

**代价**：`红儿` 同时被 `姚望舒`（380 章，全书第二主角）和 `师姐`（26 章）认领，
拉平后落到了 `师姐` 头上——`episode_assets.json` 里 **S01E01 的角色表有「师姐」
而没有姚望舒**。前 200 章里 31.5% 的角色出现都落在歧义名上。

`s13` 用的是三级判定（人工核实 > 唯一认领 > 不并），没有这个问题。
**看角色用 `season_roster.json`，别用 `episode_assets.json`。**
要修 `s11`，把它的 `amap` 换成 `s13.build_resolver()` 即可，
`selftest.py` 第 11 组已经把这几种歧义都盯住了。

## 七、动手前必须知道的几条纪律

1. **改完代码先跑 `python pipeline/selftest.py`。** 它不花钱，覆盖 10 组共 140+ 条断言。
2. **密钥只从 `.env` 读**，绝不写进代码。`.env` 已在 `.gitignore`。
3. **`source/` 是只读的。** 除非补原文，否则不要动。
4. **不要绕过逐字校验。** 任何时候产出对话/独白/旁白，都必须能在原文里逐字找到。
   如果做不到，说明方法错了，不是校验错了。
5. **改 `matrix.json` 而不是 `prompts.md`。** 后者是现拼的。
6. **推送到 `main`。** 用户明确要求过。
7. **不确定就写「不确定」。** 项目里所有文档都遵守这一条——
   `【原】` 是原文有据，`【补】` 是推断补全并注明理由，待补的另立一节。
   宁可留白，不要为了完整而猜。
