## 一、这个项目在做什么

把中文网络小说**《穿越后，系统变成白噪音了怎么办》**（作者：码字的画家，1200 个分析单元，
正文 268 万字）改编成 **AI 漫剧**——用 AI 生图 / 生视频做成 6 季 267 集的动画剧。

### 三条不可违背的原则（用户定的，任何时候不许绕过）

1. **最终目标是高质量成片。** 所有环节都要谨慎细致，人物场景必须高一致性。
2. **严格遵守原文。** 原文有多少场景人物就多少，原文怎么描写就怎么呈现。
   **人物对话、心理活动、关键旁白一条都不能漏。** 不许为了戏剧效果自行发挥。
3. **画面朴素真实，严禁浮夸。**

> 原则二是这个项目所有技术设计的源头。「逐字核验」「位置引用」「台词覆盖率」「承载账」「引用闸门」
> 这些机制存在的唯一理由就是它。**任何时候不要为了省事绕过逐字校验。**

### 原则三不是外部约束，是作者本人的审美

全文词频：「闪耀」1 次 vs「脏」152 次；书里有角色管喷火放电叫「街边杂耍」。
按原著写就是朴素的，浮夸才是背叛原文。

## 五、必须知道的坑（都是踩过的）

### 5.1 DeepSeek 的思考模式默认是开的

官方文档：「思考模式默认打开，且 effort 默认为 high」。而逐章分析是**抽取**任务不是推理题，开着它有三个坏处：
思维链和正式回复抢 `max_tokens`（长章节直接把 `content` 挤成空）、官方已载明 JSON 模式本身就有概率返回空 content、
思考模式下 `temperature` **不生效**。**代价是实打实的**：一次 500 章的跑批耗了 6 小时 45 分，只成功 9 章。

`.env` 里 `LLM_THINKING=0` 是默认值，**保持不动**。客户端永远显式声明 `thinking` 字段而不依赖服务端默认值。

### 5.2 重试必须是自适应的

对确定性错误原样重试毫无意义。每次重试都**改一个参数**：空回复 → 先摘 JSON 模式再关思考模式；
`finish_reason=length` → `max_tokens` × 1.5；JSON 解析失败 → 摘掉 JSON 模式。详见 `pipeline/README.md`。

### 5.3 出图接口的尺寸档位不通用

`gpt-image-*` 只认 `1024x1024 / 1536x1024 / 1024x1536 / auto`；**`1792x1024` 是 dall-e-3 的档位**。
拿错了网关多半包成 502「Upstream network error」，看着像网络故障。`s6` 会在发请求前自查。

### 5.4 别名归并会把全书角色塌成一个人

`s4` 用并查集归并别名。**一条错别名就能毁掉整个资产库**——seq369 把「求法真君」（唐真的名号）写成了尉天齐的别名，
不拦住会把全部角色塌成一个「唐真」。防线三道：泛称（严口径）不参与归并；**闸门建在簇上而非成对判断**
（并查集有传递性，成对检查挡不住）；人工核实过的身份 `common/names.PRESETS` 优先于自动闸门。

2026-09 的整理又收紧了一次：泛称表补全后，「凡人」「仙师」「姑娘」这类词不再能把不相干的章挂到主角名下
（唐真因此少了 2 章，姚安饶少了 1 章，都是此前并错的）。

### 5.5 `.env` 的行尾注释

`.env.example` 里写满了 `LLM_TIMEOUT=600  # 单次请求总时限` 这样的说明。解析器会剥掉行尾注释——但**只认「空白 + #」**，因为密钥里可能带 `#`。

### 5.6 别名表不能拉平成字典

`index.json` 的别名表里有 300 多个歧义名（被两个以上主名同时认领，或本身又是别的主名）。
把它拉平成 `别名 → 主名`、后写覆盖先写，谁覆盖谁只取决于索引顺序——`s11` 曾因此把「红儿」算到「师姐」头上，
S01E01 的角色表里有「师姐」而没有姚望舒。**已修**：所有需要别名 → 主名的地方（s9 / s11 / s13）都用
`common/names.build_resolver` 的三级判定，第三级不猜、原样保留并标存疑。要查一个名字归谁，用它，别自己拉表。

### 5.7 段号一律 1 基

模型看到的 `[n]`、章节 json 的 `para`、剧本声音栏的 `[n]`、取证文档的 `seqN[i]`、`s8` 卷宗、`s2m` 手写稿的 `q`——
**全部 1 基**。历史上 `s8` 与 `s2m` 曾是 0 基，照着卷宗写的卡整张偏移一位而且看不出来；`s17` 抓出来后已全部改正。
新写任何输出段号的代码，先看 `common/cite.py` 的头部说明。

### 5.8 `s10` 会改写分集表，但有剧本的集不会动

分集表是求解出来的，时长参数、卷段、章节数据任何一样变了边界都会动。第一季 47 集剧本建立在现有边界上，
所以 `s10` 把已有 `剧本.md` 的集原样锁定，只重排其余部分；如果锁定的集会被重新编号，它直接报错而不落盘。
后续季写了剧本自然也被锁住，不需要额外操作。

### 5.9 `data/` 与 `production/` 的分界，以及 `data/manual/`

`data/` 全是脚本算出来的，删了能重跑，**所以人写的东西一律不放 `data/`**（深度档案曾放在 `data/characters/`，已迁走）。
唯一例外是 `data/manual/`：人定的输入（六季定义、人工卷段），脚本只读不写。
`production/` 是人写的，删了就没了。

### 5.10 编号有四套，长得像，管的东西不同

`seq 27` 章节、`c001_唐真` 数据资产（小写，重跑会变，**别在文档里引用**）、`C01_唐真` 视觉卡（大写，人定，稳定）、
`S01E07` 集。视觉卡的号分三段归三份文件管，建新卡前先查号有没有人。全表在 `doc/14` 第六节。

### 5.11 生成模型不听否定词——要写正向结构

★ 2026-08 的教训，一次退了三张卡。红儿（`C04`）、南红枝（`C02`）出来都是**圆脸**，老拐子（`C03`）的**右脚被画成了正常脚**。
三张卡的文字其实都写了，但写法是否定式（「不做饱满感」「无婴儿肥」「不要把萎缩的右脚画成正常的脚」），
生成端压不住否定词，尤其当同一张卡里还有反向的正向词（「柔润的小鹅蛋脸」「保留娇养感」——一边否定一边要圆）。

现在是全项目的写卡规矩：**写「是什么」不写「不是什么」**（颧弓在哪、颊侧是不是内收的平面，逐项给形）；
**给可量的判据不给形容词**（红儿与南红枝共用三条线：颧弓转折 / 下颌缘 / 锁骨上窝，任一不成立即判画胖了）；
**把最要紧的那条提到提示词第一段**。否定段仍然要留作兜底，但不能当主要手段；
老拐子那张补了「反正常化」一段——生成端不但会把老人画成慈祥老爷爷，还会把残疾的身体画成健全的。

### 5.12 `【原】` 后面不要再出现第二对「」

`s17` 把 `【原】` 之后**所有** `「…」` 都当逐字引文去核验。同一行里的说明文字（「判为情绪不是骨相作废」）
用 `『』`，`s17` 不查它。反过来，真是原文却标不逐字也是错的：章号写错、省略号缩写、编者插注进了引号、
把美术指令标成 `【原】`——2026-08/09 两轮清理都是这四类。其中一条值得单记：`seq32[42]` 原文是
「它与周围的园林**风格格不入**」，早前有人以为「风」是错字删掉了；其实是「风格」与「格格不入」共用了一个「格」字。
不确定就写存疑，不改原文。

## 七、动手前必须知道的几条纪律

1. **改完任何东西先跑 `python pipeline/check_all.py`。** 不花钱，一两分钟。
2. **密钥只从 `.env` 读**，绝不写进代码。`.env` 已在 `.gitignore`。
3. **`source/` 是只读的。** 除非补原文，否则不要动。
4. **不要绕过逐字校验。** 任何时候产出对话 / 独白 / 旁白 / 取证引用，都必须能在原文里逐字找到。
   如果做不到，说明方法错了，不是校验错了。
5. **段号 1 基；引用写 `seqN[i]` + `【原】「…」`**，`s17` 会查。
6. **建新卡先查号**（`doc/14` 第六节），一个号只能指一个人。
7. **人物身份改 `common/names.PRESETS`**，带考据 `note`；改完跑第四节的重跑链路。
8. **改 `matrix.json` 而不是 `prompts.md`。** 后者是现拼的。
9. **推送到 `main`。** 用户明确要求过。
10. **不确定就写「不确定」。** `【原】` 是原文有据，`【补】` 是推断补全并注明理由。宁可留白，不要为了完整而猜。
11. **改了规矩、口径、结构，在 `CHANGELOG.md` 留一条**，写清为什么。
