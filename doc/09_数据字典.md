# 数据字典

项目里每一个数据文件、每一个字段的含义、生产者、消费者。

**读这份文档的方式**：想知道某个文件是干什么的，查第一节的总表；
想知道某个字段是什么意思，查后面对应的小节。

**一条通用约定**：全项目用 **`seq`** 作为章节的唯一主键，取值 1~1200。
不要用作者自己的章节号（`declared_num`）——它有 14 处重号、5 处跳号，
详见 `doc/01_原文数据说明.md`。

## 二、`source/novel.json`

```jsonc
{
  "meta": {
    "unit_count":        1200,    // 分析单元数。注意不等于标题行数 1222
    "merged_unit_count":   19,    // 站点把多章并在一页的单元数，这些有正文缺失
    "title_line_count":  1222,    // 原始 txt 里的标题行数
    "declared_num_min/max":       // 作者自己标的章号范围
    "total_chars":  2680694       // 剔除站点垃圾后的正文总字数
  },
  "chapters": [ {
    "seq":            1,          // ★ 全项目唯一主键，1~1200，连续无缺
    "chapter_id":     "ch0001",   // seq 的字符串形式，做文件名用
    "declared_num":   1,          // 作者标的章号。有重号和跳号，别拿来当键
    "title":          "破庙三只眼，梦里见仙班",
    "merged_titles":  [],         // 本单元并进来的其他章标题（is_merged 时非空）
    "is_merged":      false,      // 站点合并页 → true，这类单元正文不全
    "line_start/end": 12,         // 在原始 txt 里的行号，用于回溯
    "char_count":     3182,
    "paragraph_count": 63,
    "stripped_lines": [           // 被剔除的行，留痕不丢
      {"line": 45, "kind": "站点插入", "text": "本小章还未完，请点击下一页…"}
    ],
    "paragraphs":     ["…", "…"]  // ★ 正文，按段落切好。所有引用的段号都指它
  } ]
}
```

> **为什么只存 `paragraphs` 不存整段 `text`**：两者都存会让文件从 8.9MB 涨到 16.8MB，
> 而 `text` 随时可以 `"\n".join(paragraphs)` 得到。

### 三个最容易搞混的质量指标

| 指标 | 问的是 | 谁算的 | 门槛 |
| --- | --- | --- | --- |
| `verbatim_rate` | 抽出来的引用**在不在原文里** | 程序，客观 | 95% |
| `dialogue_coverage` | 原文的台词**有没有被漏掉** | 程序，客观 | 90% |
| `fidelity_score` | 整体一致性如何 | 模型，主观 | 90 |

> 前两个是**互补**的：一个防「编造」，一个防「漏抄」。只看前者会漏掉整段没抽的情况。
> 当前全书两项都是 **100%**。三个都是闸门（`common/quality.gate`）；审查员列出的 `missing_items` 不是——它只作修订轮的输入。

## 四、`data/characters/`

### `index.json`　角色总表

```jsonc
{
  "built_from_chapters": 1200,
  "character_count": 997,
  "alias_merge": true,
  "suspicious_merges": [],     // 归并后一个簇里有多个高频名 → 可能并错了，待人工看
  "rejected_merges": [ {       // ★ 被拒绝的归并，留痕待复核
    "seq": 369,                // 哪一章提出的
    "name": "尉天齐", "alias": "求法真君",
    "name_side": ["尉天齐"], "alias_side": ["唐真"],
    "reason": "两边各自已包含独立主名，拒绝归并"
  } ],
  "characters": [ {
    "id": "c001_唐真",
    "canonical_name": "唐真",   // 归并后的主名
    "aliases": ["真君", "三只眼", …],
    "first_seq": 1, "last_seq": 1200,
    "chapter_count": 634,       // ★ 排序与筛选都用它
    "role_distribution": {"主导": 378, "提及": 176, …}
  } ]
}
```

> **`rejected_merges` 是什么**：某一章把 A 写成了 B 的别名，但 A 和 B 各自都是独立主角。
> 这一定是那一章写错了，程序拒绝合并并留痕。seq369 那条就是典型——
> 它把唐真的名号「求法真君」写成了尉天齐的别名，不拦住就会把两个主角焊死。
> 详见 `s4_build_assets.py` 的注释。

### `cNNN_名字.json`　单角色资产

```jsonc
{
  "id": "c001_唐真", "canonical_name": "唐真",
  "aliases": [...], "chapters": [1,2,3,…],   // 出场的所有 seq
  "role_distribution": {...},

  "states":  [ {"seq":1, "state":"修为尽失…"} ],
  "actions": [ {"seq":1, "actions":["从噩梦中惊叫坐起", …]} ]
}
```

### `data/dossiers/dossier_名字.json`　角色卷宗（与上面不同；`.json` 不入库，`.md` 是它的阅读稿）

`cNNN` 是**聚合后的结论**；`dossier` 是**原始证据**——该角色在全书出现过的
**每一段原文**，连同前后各 2 段上下文。写角色深度档案时用它，
因为结论可以错，原文不会错。

```jsonc
{

  "exclude": ["寿与天齐"],                    // 含别名但另有所指的词组，如成语
  "note": "别名边界的考据说明（为什么这么定）",
  "stats": {
    "total_mentions": 4244, "chapters_with_mention": 458,
    "by_alias": {"红儿": 2340, "姚望舒": 1023, …},
    "alias_first_seen": {"红儿": {"seq":2,"para":5}, …},   // para 1 基
    "densest_chapters": [...],                // 戏份最重的 40 章
    "by_tag": {"外貌":1209, "情绪":551, …}     // 主题标签命中数
  },
  "tag_index": {"外貌": [{"seq":1,"para":12}, …]},   // 按主题查证据
  "chapters": [ {
    "seq": 2, "title": "…", "hit_count": 7,
    "hits": [ {                                // 命中段（＝证据）
      "para": 5, "text": "…原文…",
      "aliases": {"红儿": 1}, "tags": ["身份"],
      "speech": [ {                            // 段内的引号台词
        "quote": "赵叔，你说…",
        "likely_speaker": "很可能"              // 很可能 / 可能 / 待定
        //  ★ 只给线索不下结论。宁可标待定，也不替原文给角色分配台词
      } ]
    } ],
    "ambiguous": [...],                        // 存疑别名的命中，单独放
    "context": [ {"para": 4, "text": "…", "hit": false} ]   // 前后文
  } ]
}
```

## 六、`data/plot/` 的核心几个

### `timeline.json`　每章一条的机器可读摘要

```jsonc
[ {
  "seq": 1, "title": "…", "synopsis": "…",
  "characters": ["唐真","老拐子",…],   // 只留出场≥8章的主要角色，龙套不入
  "scenes": ["城隍庙", …],
  "tone": "梦境的暴烈羞辱…",
  "foreshadows": ["…"], "reveals": ["…"],
  "beat_count": 7, "dialogue_count": 40, "char_count": 3182
} ]
```

### `data/manual/seasons.json`　六季定义（**这份是人定的，随时可改**）

```jsonc
[ {"name": "白噪音", "seq_start": 1, "seq_end": 200,
   "finale": "白玉蟾陨落的余波散尽，紫云提头西归"} ]
```

改了它之后跑 `s12` → `s10` → `s11` → `s13` 重排下游即可；已有剧本的集边界不会动。

### `arcs.json`　卷段边界

```jsonc
{
  "meta": {"window": 8, "min_hits": 3, "cut_cost": 0.8, "exit_min_chapters": 15, "arc_count": 90},
  "arcs": [ {
    "season": 1, "seq_start": 1, "seq_end": 41, "chapters": 41,
    "score": 0.84,              // 变更分：前后各 8 章的核心阵容有多不一样
    "cut": "软断",               // ★ 硬断 / 软断
    "exits": [],                // 这一章之后再也不出现的主要角色
    "title_at_cut": "…"
  } ]
}
```

> **硬断 vs 软断**：硬断＝有主要角色从此不再出现（客观事实）。
> 分集器**绝不允许**一集跨过硬断点；软断只是「优先在此收尾」的倾向。
> 为什么只认角色退场，见 `doc/08` 第 4.5 节的对照表。

### `episodes.json`　分集表

```jsonc
{
  "meta": {"chars_per_sec": 4.5, "pause_factor": 1.2,
           "target_min": 28.0, "episode_count": 267},
  "episodes": [ {
    "code": "S01E01",            // ★ 集号，全项目用它指代一集
    "season": 1, "season_name": "白噪音", "episode": 1,
    "seq_start": 1, "seq_end": 4, "chapters": 4,
    "minutes": 28.2,             // 求解器排边界用的估值，不是成片验收标准
    "cut": "卷段中",              // 这一集收在哪种断点上
    "locked": true               // 已有 剧本.md，s10 重跑时原样保留，不重排
  } ]
}
```

**时长怎么算的**：`语音字数 ÷ 4.5 字每秒 × 1.20`。
系数 1.20 来自 E01/E02 两集人工试点的实测，见 `doc/08` 第五节。

### `episode_assets.json`　每集的资产需求

在 `episodes.json` 每条的基础上加：

```jsonc
{
  "characters": [...], "scenes": [...],       // 这一集出现的全部
  "new_characters": [...], "new_scenes": [...],  // ★ 其中首次出现的
  "asset_load": 35                            // 新角色×2 + 新场景，排产用
}
```

> **为什么要单列「首次出现」**：角色和场景的提示词只做一次，之后全片复用——
> 这正是一致性的来源。真正的工作量是「有多少是新的」，不是「有多少个」。

> 角色列的归属用 `common/names.build_resolver` 三级判定（PRESETS > 唯一认领 > 不猜）。
> 此前它把别名表拉平成字典、后写覆盖先写，`红儿` 落到了 `师姐` 头上——已修。
> 判不了归属的名字原样保留并列进 `ambiguous_characters`，供人判。

### `season_roster.json` / `.md`　按季的资产清单

```jsonc
{
  "seasons": [{
    "season": 1, "name": "白噪音", "seq_start": 1, "seq_end": 200,
    "episodes": 47, "episode_start": "S01E01", "episode_end": "S01E47",
    "character_count": 203, "scene_count": 274,
    "characters": [{
      "name": "姚望舒",
      "season_chapters": 114,        // 本季出场章数，按章去重
      "book_chapters": 380,          // 全书出场章数
      "first_seq": 2, "first_episode": "S01E01",
      "debuts_this_season": true,    // 全书首现就在本季 = 要从零做资产
      "tier": "主要",                 // ≥10 章主要 / 3~9 次要 / 其余龙套
      "ambiguous": false,            // ★ 归属存疑，本表按字面保留没并给谁
      "claimed_by": null,            // 存疑时列出认领它的主名
      "has_dossier": true,           // 有没有人工深度档案
      "has_card": false              // production/characters 或 scenes 里有没有它的卡（母版提示词在，按名字匹配）
    }],
    "scenes": [{ /* 同构，另有 types 室内外统计 */ }]
  }]
}
```

**归属判定分三级，级别不够就不并**：

| 级 | 依据 | 例 |
| --- | --- | --- |
| 1 | `common/names.PRESETS`（17 个人工逐字核实过的身份） | `红儿 → 姚望舒` |
| 2 | 索引里**只有一个主名认领**的别名 | `三只眼 → 唐真` |
| 3 | 多方认领 / 本身也是主名 / 人工标了存疑 | `师姐` 原样保留，标存疑 |

第三级**不猜**。宁可清单里多一个「师姐」让人自己判，也不悄悄算到某人头上。

`season_roster.md` 末尾把存疑名分成三类，每类都可直接动手：
**A** 疑似同人异名（30 对互认，其中 9 对互为子串，几乎必是同一人）、
**B** 疑似把地点抽成了人（7 个，同时出现在角色和场景索引里）、
**C** 其余（以泛称为主）。

### `.run/reports/quality_report.json`　体检报告（不入库，每次重写）

```jsonc
{
  "total_chapters": 1200, "analyzed": 1200, "problem_count": 32,
  "tiers": {                       // ★ 按严重程度分三级；退出码只看 T1 / T2

  "enum_drift": {…},               // 枚举外取值的分布，只统计不判错
  "details": [ {"seq":1, "problems":[], "verbatim_rate":1.0, …} ]

```

## 七、`production/style_test/matrix.json`　画风选型矩阵

```jsonc
{
  "meta": {"aspect_ratio": "16:9", "repeats_per_cell": 3,
           "design_principle": "十个画面目标的描述一律画风中立…只有单一变量变化才是受控对比"},
  "shared": {
    "prefix":   "中式古代题材，16:9 横向宽画幅构图。",     // 拼在最前
    "suffix":   "整体低饱和；所有布料有织纹与磨损…",       // 拼在最后
    "negative": "璀璨, 绚烂, 华丽, …"                    // 反面词
  },
  "targets": [ {                 // ★ 纵轴：10 个画面目标
    "id": "T03", "name": "老年角色特写·反美化",
    "why": "★ 最关键的一测…",      // 为什么要测它
    "key_check": "出来的人必须让你觉得不太想靠近…",  // 看图时看什么
    "desc": "…",                 // ★ 画面描述，画风中立，只写有什么不写怎么渲染
    "negative_extra": "慈祥, 和蔼, …"
  } ],
  "styles": [ {                  // ★ 横轴：11 个画风（S9~S11 是国风三维的三个变体）
    "id": "S6", "name": "成人向写实三维武侠",
    "family": "三维", "ref": "《画江湖之不良人》第五季",
    "brief": "…",                // 一句话简介，显示在大图表头
    "suffix": "画风：三维CG成人向半写实…",   // ★ 只写渲染方式，不改画面内容
    "negative_extra": "二维, 线稿, 平涂, …"
  } ]
}
```

**最终提示词 = `shared.prefix` + `target.desc` + `style.suffix` + `shared.suffix` +
「务必避免出现以下要素：」+ 三处 negative 去重合并**。

> 接口（OpenAI Images API）**没有 negative_prompt 字段**，所以反面词只能折进正文。
> 也因此 `prompts.md` 是**每次现拼的**，手改它不会生效——要改就改 `matrix.json`。

## 八、字段命名的几条约定

| 约定 | 说明 |
| --- | --- |
| `seq` | 章节主键，1~1200。**任何地方的章节号都是它** |
| `seq_start` / `seq_end` | 章节区间，**含两端** |
| `para` | 段号，**从 1 开始**（不是 0） |
| `para_range` | `[起, 止]`，含两端 |
| `code` | 集号，格式 `S01E01` |
| `chapter_count` | 出场/出现的**章数**，不是次数 |
| `total_mentions` | 提及**次数**，一章可以多次 |
| `_filled` | 值为 `true` 表示这条是 `s5` 补进去的，不是模型抽的 |
| `locked` | 分集表里值为 `true` 的集已有剧本，边界不再重排 |
| `【原】` / `【补】` | 只在 md 文档里用：原文有据 vs 推断补全 |
