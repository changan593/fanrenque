# 章节分析规范

阶段二的完整规范。**这一步是整个项目的基石**——角色资产、场景资产、分季分集、
分镜脚本全都建在这 1200 份 json 上。这里放过一个错误，后面几百集都带着它。

## 一、设计出发点

用的是 deepseek-v4-flash，小模型。小模型在这个任务上有两个固定弱点：

1. **顺手改写**——把「又来了！又来了！我早就说了嘛」写成「又来了又来了，我早说过」，
   读起来一样，但违反原则二。
2. **凭印象补话**——原文没有的台词，它觉得「这里该有一句」就补上了。

让模型自己审自己抓不住这两类错，因为它看不出自己改过。
所以本管道的核心设计是：**用程序做客观核验，再把客观结论喂给模型当审查证据。**

## 二、每章的处理流程

每章固定三次模型调用，不达标追加一轮修订。

| 顺序 | 环节 | 类型 | 干什么 |
| --- | --- | --- | --- |
| ① | `extract` | 模型 | 抽取人物/场景/对话/独白/旁白/节拍/简介 |
| ★ | **逐字核验** | **程序** | 每条引用回原文精确匹配，判定 逐字/改写/臆造；另算台词覆盖率 |
| ② | `structure_review` | 模型 | 审结构完整性 + 跨章命名一致 + 上下文衔接（回喂前 3 章简介） |
| ③ | `fidelity_review` | 模型 | 审臆造/改写/遗漏/张冠李戴，**以★的结论为客观证据** |
| ④ | `repair` | 模型 | 仅在不达标时触发：删臆造、改回原文、补遗漏，然后重跑★和③ |

### ★ 逐字核验怎么做的

把模型摘出来的每条引用，和原文做归一化后的字符串匹配：

- 归一化：全角转半角、中英标点统一、去掉所有空白
  （所以「标点写成半角」不算错，「改字」一定算错）
- **exact** —— 原文里逐字存在。同时检查模型自报的段落号对不对。
- **near** —— 找不到逐字，但滑窗相似度 ≥ 0.70。判定为模型改写了。
- **miss** —— 相似度 < 0.70。原文里根本没有，判定为臆造。

实测标定：加一个字的改写 0.96、整句改写 0.6~0.8、凭空编造 < 0.5。

参与核验的字段：`dialogues[].text`、`monologues[].text`、`narration[].text`、
`characters[].appearance_quotes[]`、`scenes[].description_quotes[]`。

另外算**台词覆盖率**：用正则扫出原文所有引号内容，看有多少条没进 `dialogues`。
编造和遗漏一样致命，这项专门盯遗漏。

### 为什么正文要按段落编号喂给模型

输入原文时每段带 `[n]` 编号，要求每条引用标注所在段号。好处有二：
一是模型被迫回原文定位而不是凭记忆写，抽取准确率明显更高；
二是程序能验证段号对不对，多一个客观信号。

## 三、质量闸门

四条全过才算合格，任一不过就触发修订轮：

| 闸门 | 门槛 | 出处 |
| --- | --- | --- |
| 结构审查分 | ≥ 85 | 模型 ② |
| 一致性审查分 | ≥ 90 | 模型 ③ |
| 逐字命中率 | ≥ 95% | 程序 ★ |
| 臆造条数 | = 0 | 程序 ★ |

阈值在 `pipeline/config.py` 里，可调。

修订轮上限默认 1 轮（`PIPELINE_REPAIR_ROUNDS`）。
修完仍不达标的章节会落盘并标记 `quality.passed = false`，
由 `s3_validate_chapters.py` 统一列出来，人工处理或调参重跑。

**字段与需求的对应**（你提的最低要求全部覆盖）：

| 你的要求 | 字段 |
| --- | --- |
| 章节序号 | `seq` / `declared_num` |
| 章节标题 | `title` |
| 章节涉及人物 | `analysis.characters` |
| 章节涉及场景 | `analysis.scenes` |
| 章节剧情简介 | `analysis.synopsis` |
| 章节原文 | `raw_text` / `paragraphs` |
| 章节独白 | `analysis.monologues` |
| 章节对话 | `analysis.dialogues` |
| 审查记录（分数 + 详细分析） | `reviews[]` |

在此之上补的字段，都是为后面分镜和资产服务的：
`narration`（你要求的关键旁白不能漏）、`beats`（分镜节拍）、
`appearance_quotes` / `description_quotes`（原则二：原文怎么描写就怎么呈现）、
`props` / `terms`（世界观一致性）、`continuity`（伏笔追踪）。

## 五、跨章一致性怎么保证

三个机制：

1. **人名登记表**：抽取时把已完成章节里出现过的人物主名传给模型，
   要求统一写法（本章写「三只眼」也归到主名「唐真」，「三只眼」进 `aliases`）。
   同时明确禁止据此把本章没出现的人写进来。
2. **前文提要回喂**：结构审查时输入前 3 章简介，专门审「同一个人前后叫法有没有漂移」
   「有没有出现前文从未铺垫却当作已知的设定」。
3. **`--phase review` 二轮**：首轮并发跑时靠后的章节可能读不到紧邻前几章的简介。
   全书跑完后再跑一次 `--phase review --force`，此时全书简介齐全，
   能拿到完整上下文的审查结论，成本只有一次审查的钱。**建议做这一轮。**

## 六、验收

```bash
python pipeline/s3_validate_chapters.py
```

不调 API，纯程序校验，随便跑。它会**重算**逐字命中率（不信任落盘时记的值），
另外查：必填字段、简介长度、人物条目重复、场景里出现未登记人物、
说话人不在人物名单、审查留痕是否齐全、调用次数是否够 3 次。

输出终端摘要 + `data/plot/quality_report.json` + 需要重跑的 seq 列表：

```bash
python pipeline/s3_validate_chapters.py --rerun-list
```

### 建议的验收标准

| 指标 | 目标 |
| --- | --- |
| 逐字命中率均值 | ≥ 99% |
| 臆造（miss）总数 | 0 |
| 台词覆盖率均值 | ≥ 98% |
| 一致性审查分均值 | ≥ 93 |
| `passed = false` 的章节 | ≤ 2%，且逐章人工过一遍 |

**先跑 3 章人工逐字比对，确认质量够格再跑全书。** 全书重跑一次的成本不低。

## 七、合并单元的特殊处理

19 个 `is_merged: true` 的单元（原文缺失，见 `doc/01`）在抽取时会额外告知模型：
「本单元是原站点把多章合并在一页，请按实际正文内容解析，
不要为没有正文的标题编造情节」。

**缺失的内容不会被悄悄编出来**，这些单元的分析结果会明显短于相邻章节，属预期行为。
