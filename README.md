# fanrenque

把网络小说《穿越后，系统变成白噪音了怎么办》（码字的画家 著，1200 章 / 290 万字）
改编成 **AI 漫剧**。

**6 季 268 集**，每集 2~5 章、25~32 分钟。

## 三大原则

1. **最终目标是高质量成片** —— 所有环节谨慎细致，人物场景高一致性
2. **严格遵守原文** —— 原文有多少人物场景就多少，怎么描写就怎么呈现，
   对话、心理活动、关键旁白一个不漏
3. **画面风格朴素真实** —— 严禁浮夸

展开见 [`doc/00_项目总纲.md`](doc/00_项目总纲.md)。三条原则在整个项目里是硬约束，
下游任何环节都不许绕过——尤其是原则二，它落实成了程序化的逐字核验闸门，不靠模型自觉。

## 目录

每个目录一句话；每个文件、每个字段的详细含义见 [`doc/09_数据字典.md`](doc/09_数据字典.md)。

```
source/          原文。★只读，任何脚本都不许改它★
  ├── *.txt              抓下来的原始文本（GB18030）
  ├── novel.json         标准化原文，1200 个分析单元，后续一切的输入
  └── novel.index.json   轻量目录（不含正文），做规划时加载这个省内存

data/            机器产出的数据资产，全部可由 pipeline 重新生成
  ├── chapters/          逐章分析，一章一个 json，共 1200 个（阶段②产出）
  ├── characters/        角色资产 973 个 + 14 份深度档案（阶段③）
  ├── scenes/            场景资产 1364 个（阶段③）
  └── plot/              全书结构：剧情线、六季、分集表、长线、体检报告

pipeline/        脚本管道，编号即执行顺序 —— 见 pipeline/README.md
  ├── s0 ~ s12           各步骤脚本，只有 s2 / s6 花 API 的钱
  ├── config.py          所有可调参数的唯一来源（读 .env）
  ├── common/            路径、JSON、LLM 客户端、逐字核验器、进度看板
  ├── prompts/           四个提示词，纯文本，改了立即生效，不用动代码
  ├── schemas/           章节分析 JSON 的结构约定
  └── selftest.py        离线自测，用假模型跑通全流程，不花额度

production/      人工产出的成片素材，与 data/ 的区别是「这些不可重新生成」
  ├── s01/               第一季：分集方案、角色/场景资产卡、E01/E02 剧本
  └── style_test/        画风选型矩阵的提示词与配置

doc/             文档 00~10，见上面的「我想…… 该看哪份文档」
```

**`data/` 与 `production/` 的分界线**：`data/` 全部是脚本算出来的，删了能重跑；
`production/` 是人（或模型逐字读原文）写出来的，删了就没了。
所以改 `production/` 里的东西要当心，改 `data/` 里的东西一般应该去改产生它的脚本。

## 快速上手

```bash
pip install -r requirements.txt
cp .env.example .env          # 填 DEEPSEEK_API_KEY / IMAGE_API_KEY，.env 不入库
python pipeline/selftest.py   # 离线自测，验管道通不通，不花额度
```

想确认现有数据是否完好（三条命令，都不花钱，约一分钟）：

```bash
python pipeline/s3_validate_chapters.py     # 期望：问题章 0
python pipeline/s10_episode_plan.py         # 期望：268 集
python pipeline/selftest.py                 # 期望：全部通过
```

密钥只从 `.env` 或环境变量读，**任何时候都不写进代码、不进版本库**。

## ⚠ 两件必须先知道的事

**一、全书不是 1232 章，是 1222 个章节标题、1200 个分析单元。**
作者自己有 14 处重号、5 处跳号；站点又把部分章节合并在一页。
所以全项目的主键是文件顺序 `seq`（1~1200），不是作者的章号。
见 [`doc/01_原文数据说明.md`](doc/01_原文数据说明.md) 第二节。

**二、第 1115~1213 章（结尾段）内容有缺失，约 22 章的正文没抓下来。**
影响第六季（大结局），前五季原文完整、不影响开工。
明细见 [`doc/01_原文数据说明.md`](doc/01_原文数据说明.md) 第三节。
