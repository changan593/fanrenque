# fanrenque

把网络小说《穿越后，系统变成白噪音了怎么办》（码字的画家 著，1200 个分析单元，正文 268 万字）
改编成 **AI 漫剧**：**6 季 267 集**，每集 2~5 章。**时长不做预设**——一集多长是内容量的结果，
不是先定后写的指标（见 [`doc/00_项目总纲.md`](doc/00_项目总纲.md) 第二节）。

## 三大原则

1. **最终目标是高质量成片** —— 所有环节谨慎细致，人物场景高一致性
2. **严格遵守原文** —— 原文有多少人物场景就多少，怎么描写就怎么呈现，
   对话、心理活动、关键旁白一个不漏
3. **画面风格朴素真实** —— 严禁浮夸

三条原则在整个项目里是硬约束，下游任何环节都不许绕过。原则二落实成了三道程序闸门，不靠模型自觉：
章节层 `s3`（每条引用回原文逐字核验 + 台词覆盖率）、剧本层 `s14`（每条关键旁白都要在剧本里有承载）、
取证层 `s17`（角色卡 / 场景卡 / 幕文档里每处 `【原】「…」` 都逐字落在所标段号）。
一条命令跑全部闸门：`python pipeline/check_all.py`。

## 目录

每个目录一句话；每个文件、每个字段的详细含义见 [`doc/09_数据字典.md`](doc/09_数据字典.md)。

```
source/          原文。★只读，任何脚本都不许改它★
  ├── *.txt              抓下来的原始文本（GB18030）
  ├── novel.json         标准化原文，1200 个分析单元，后续一切的输入
  └── novel.index.json   轻量目录（不含正文），做规划时加载这个省内存

data/            机器产出的数据资产，删了能重跑（data/manual/ 例外）
  ├── chapters/          逐章分析，一章一个 json，共 1200 个（s2 / s2m / s5）
  ├── characters/        角色资产 997 个 + index.json（s4）
  ├── scenes/            场景资产 1364 个 + index.json（s4）
  ├── dossiers/          17 份角色原文卷宗的阅读稿（s8；机器读的 json 不入库，秒级可重跑）
  ├── plot/              剧情线、卷段、分集表、每集资产、按季清单（s0 / s4 / s9 ~ s13）
  └── manual/            ★ 人定的输入：seasons.json 六季定义、人工卷段、一次性分析产物

pipeline/        脚本管道，编号即执行顺序 —— 见 pipeline/README.md
  ├── s0 ~ s18           各步骤脚本，只有 s2 / s6 花 API 的钱
  ├── check_all.py       ★ 一键跑全部闸门（selftest / s3 / s14×47 / s15 / s17 / s18）
  ├── config.py          所有可调参数的唯一来源（读 .env）
  ├── common/            路径、命名、引用记法、质量闸门、逐字核验、LLM 客户端……
  ├── prompts/           四个提示词，纯文本，改了立即生效
  ├── schemas/           章节分析 JSON 的字段口径说明
  └── selftest.py        离线自测，196 条断言，不花额度

production/      人工产出的成片素材，与 data/ 的区别是「这些不可重新生成」
  ├── style_assets/      ★ 全片「怎么画」的唯一入口：统一风格 / 角色提示词 + 场景参考包
  ├── characters/        跨季人物视觉资产：CNN_ 具名卡、GNN_ 群像卡；_深度档案/ 14 份人写档案；_归档/
  ├── scenes/            跨季场景视觉资产：SNN_ 场景卡（母版 + 状态）
  ├── s01/               第一季：分集方案、总则、角色 / 场景取证、视觉基准补充、47 集剧本与幕文档、E01 出图台账
  └── style_test/        画风选型矩阵的配置与留痕（选型已结束）

doc/             文档 00~05、08~11、13~16；archive/ 放选型期的 06、07、12
CHANGELOG.md     变更与决策记录
.run/            运行期日志与体检报告，不入库
```

**`data/` 与 `production/` 的分界线**：`data/` 全部是脚本算出来的，删了能重跑；
`production/` 是人（或模型逐字读原文）写出来的，删了就没了。
所以改 `production/` 里的东西要当心，改 `data/` 里的东西一般应该去改产生它的脚本。
`data/manual/` 是唯一的例外——它装的是人定的输入，脚本只读不写。

## 快速上手

```bash
pip install -r requirements.txt
cp .env.example .env              # 填 DEEPSEEK_API_KEY / IMAGE_API_KEY，.env 不入库
python pipeline/check_all.py --quick   # selftest + s3 + s15 + s17，约一分钟，不花钱
python pipeline/check_all.py           # 再加 47 集的 s14 与出图台账 s18，约 70 秒
```

期望：selftest / s15 / s17 / s18 / s14 全绿；`s3` 会报出下面「已知欠账」里的 29 章，那是已知状态，不是新问题。

密钥只从 `.env` 或环境变量读，**任何时候都不写进代码、不进版本库**。

## 已知欠账

按轻重排。全部记在 [`doc/03_路线图.md`](doc/03_路线图.md)，这里只列会让闸门变红或让人误判的：

1. **29 章审查分低于合格线**（`s3` 的 T2）。修订轮用尽后结构分 < 85 或一致性分 < 90，
   `s2` 记为 failed 等着重跑。需要 API：`python pipeline/s2_analyze_chapters.py --redo-failed`。
   这些章的逐字率与台词覆盖都是 100%，问题在模型审查员给的分，不在引用。
2. **3 章有段号越界的引用**（ch0350 / ch0670 / ch1141，`s3` 的 T3）：`para` 落在 1~段数之外。写到这些章的剧本时以原文为准。
3. **第 1115~1205 章之间 41 章正文被截**，影响第六季。见 [`doc/11`](doc/11_待补原文清单.md)。
4. **卷段是算法版**（90 段，只约六成边界站得住），只作分集的软约束；人工卷段只做了 seq201~400 一块。见 [`doc/08`](doc/08_全书剧情线.md) 4.5。
5. **第一季只有 E01 有分镜草图**，画面提示词层写到 E10。
6. **E01 的 20 张角色卡、23 张场景卡通过人工验收 0 张**，验收通过前不许开工出图（`doc/16` 第二节）。

## ⚠ 两件必须先知道的事

**一、全书不是 1232 章，是 1222 个章节标题、1200 个分析单元。**
作者自己有 14 处重号、5 处跳号；站点又把部分章节合并在一页。
所以全项目的主键是文件顺序 `seq`（1~1200），不是作者的章号。
见 [`doc/01_原文数据说明.md`](doc/01_原文数据说明.md) 第二节。

**二、第 1115~1205 章之间有 41 章的正文被截了，缺约 5.0 万字。**
影响第六季（大结局），第 1~1114 章与第 1206~1213 章完整，不影响前五季开工。
要补哪些章、补完怎么重跑，见 [`doc/11_待补原文清单.md`](doc/11_待补原文清单.md)。
